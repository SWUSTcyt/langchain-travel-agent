# 模型 / 外部服务 / 连接器工程指南

> 按需读取的参考文档，不常驻 skill 正文。**只在实现「接模型 / 外部服务 / 付费或联网 connector」的功能时读**；纯前端/CRUD/离线工具不触发。
> 被 `execute-implement`、`verify-test` 以「详见本文」的形式引用。操作型清单另见 `templates/connector-isolation-checklist.md`。

本指南收纳四组规则：失败关闭门禁、三层不变量（实现侧）、失败关闭负例 + 质量数据四层隔离（测试侧）、外部连接器协议。核心判断：**危险错误往往不发生在 API 报错，而发生在「证据不足却继续产出确定结论」。**

---

## 一、失败关闭与调用前门禁（实现侧）

按顺序落三件事：

1. **先宿主 preflight，再外部请求。** 由宿主（你的代码）先做证据资格、权限、版本、输入上限、来源可达性检查；**只有 preflight 通过才允许调用模型/外部服务产生确定结论**。preflight 不过就落一个可见失败终态（`blocked`/`unverified`/`no_match`/`pending_external`），不调用。
2. **结构化输出用互斥终态 + 交叉字段校验。** 输出字段直接对应宿主终态（如 `verified/partially_verified/unverified` 三态互斥），不要让宿主从二分类字段二次猜测；数字/范围/风险等级等高风险字段做交叉校验。
3. **每种异常都要有可见状态。** 证据不足、版本冲突、权限失败、输入超限、来源不可访问、外部返回空/超时/HTTP 错误/错误 schema/部分结果——都不得静默变成成功。

**不允许让模型自己把候选、转载或搜索摘要提升为 `verified`**；证据资格由宿主用门禁决定，模型只消费已通过门禁的证据。

## 二、三层不变量（实现必须同时覆盖）

高风险问题多是信息在层与层之间丢失（意图→规格→授权→证据资格→模型输入→结构化结果→人工确认→产物→审计）。写这类功能时同时落三层，缺一层不能只因「API 能返回 JSON」就标实现完成：

1. **领域不变量** — 来源、权限、版本、用户确认范围、删除谱系等**不可由模型决定**的规则，由宿主强制。
2. **外部/模型契约** — 输入投影（只喂有界输入）、结构化输出、字段互斥、上下文预算、provider 特定参数。
3. **宿主状态机** — 正常 / 边界 / 失败 / 恢复 / 重放 / 并发 / 外部依赖缺失，各自的终态明确。

**文档/文件改写类功能**额外落一条确定性链条：`原稿 digest → 建议锚点 → 用户确认项 → 副本逐段差异 → 回退/删除`。金额、主体、期限、IP、责任上限、管辖等高风险字段不能由模型默认选定；原稿与副本必须可区分。

## 三、失败关闭负例（测试侧，必做）

只测「有证据时能正确产出」不够，必须同时测「证据不足时能正确不产出」。每个依赖模型或外部服务的功能，至少补一条失败关闭负例：

- **零调用负例**：构造证据不足/权限失败/版本冲突/条目不存在等场景，断言 `model_calls == 0`（或外部调用为 0），且终态落在预期的 `blocked`/`unverified`/`no_match`/`pending_external`，而不是 `succeeded`。
- **四态一致断言**：一条断言同时覆盖①系统终态②用户可见文案③审计事件④数据库/存储终态，四者必须一致——防止「文案说没核验，状态却是完成」。
- **外部异常不静默成功**：外部返回空、超时、HTTP 错误、错误 schema、部分结果时，断言不会被当成成功；候选/转载/搜索摘要不会被自动升级为 `verified`。

## 四、质量数据四层隔离（有质量基线/评测的功能）

工程测试容易先得到一大片绿，但业务质量缺少样本代表性和盲测隔离。把质量数据分四类，状态不可混写：

| 层 | 用途 | 能证明什么 | 调参 |
|---|---|---|---|
| development fixture | 开发夹具，可调可重复 | 链路能跑 | 可 |
| public regression | 公开材料回归 | 不回退 | 可 |
| calibration | 校准/调参样本 | 参数合理 | 可，但记录版本+变更 hash |
| blind set | 盲测集，首次运行即消费 | 业务质量边界 | **禁止读取答案调参** |

- 任何提示词/规则调优都不得读取 blind set 答案；提示词变化要生成新数据版本和 hash。
- 质量报告必须写：**样本量、基线、通过率、失败项、适用范围**；单题或合成样本输出明确的「不可推广」标签。

## 五、外部连接器协议（普通测试默认断网）

接入付费/联网/外部 connector 的功能，测试必须默认隔离，否则本机 `.env` 的开关会污染普通测试（真实事故：本地证据卡测试意外联网、终态从 `succeeded` 漂成 `partial`）：

- 普通单元/功能测试启动时，用**进程级** autouse fixture 把所有可选 connector 覆盖为 false——不能只在单个测试里关，进程级配置污染盖不住。
- 真实 E2E 只能通过显式 `RUN_REAL_*` 开关 + 独立测试标记打开，默认 skip；有独立环境、明确超时、脱敏回执、零正文日志。
- 连接器回执只保留 `connector/status/count/latency/error_code`；**不整体序列化** headers/auth/URL query/原始 payload。
- 运行前打印一行「连接器状态摘要」（开/关），但绝不打印凭据。

逐项操作清单与通用 fixture 伪代码见 `templates/connector-isolation-checklist.md`；诊断字段白名单与凭据泄露处置见 `execute-implement` 的密钥纪律。
