# Issue: 行程记忆按会话隔离，不覆盖本句城市，不误认天数

> 状态：已完成。2026-10-20 用户确认后先写失败测试，再改代码。
> 来源：`docs/reviews/2026-10-20-pre-merge-review.md` 的三条 P1。

## 任务描述

城市、天数、节奏的跨轮记忆只属于当前浏览器会话，不和其他标签页共用；页面刷新或新开对话后从空开始。

本句说了城市（包括不在内置城市表里的城市）时，不能用上一轮的城市替换。

「第一天」「第二天」这类序数词不当作行程天数。

## 规格未写、合理用户会踩

| 输入或情况 | 合理用户期望 | 落到哪条测试 |
|---|---|---|
| 先问成都，再问「丽江今天天气」 | 工具收到丽江，或至少不被改成成都 | 新增失败测试，先红后绿 |
| A 标签页在问成都，B 标签页新开问「推荐景点」 | B 不继承成都 | 新增失败测试，先红后绿 |
| 「第一天去宽窄巷子，第二天去熊猫基地，一共三天」 | 天数是三天 | 新增失败测试，先红后绿 |
| 先说成都，再说「改成两天」 | 仍是成都，天数变两天 | 现有 `test_followup_without_city_keeps_previous_city_and_updates_days` 保持通过 |

## 实现方向

- 每轮由 `ui.stream_answer` 根据本会话的 Gradio 历史重新算出城市和约束（`TripState`），以 agent 运行上下文 `context=` 传给中间件（`create_agent(context_schema=TripState)`），不再用进程级全局变量。
- 与确认时的偏差：确认稿写「只看上一轮用户原话」。实现改为「本会话用户原话里最近一次提到的值」，因为「成都三天 → 加个美食 → 改成两天」只看上一轮会丢城市。这些原话只用来算状态，不进模型上下文；模型上下文仍只有上一轮原话和最终答案。
- 本句提不到城市、但模型在工具参数里给了城市时，不强行改写成上一轮城市；只在模型没给城市时补上。
- 天数正则排除前面紧跟「第」或数字的情况（「第十二天」不会被拆成「二天」）。
- 顺带修复：`enforce_city_on_tools` 原先在 try 里调用工具，工具本身抛错会被报成「城市注入失败」。改为准备阶段在 try 里，工具调用移到 try 外。
