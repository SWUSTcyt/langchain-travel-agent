# Issue: 没对上的地点由页面补搜再补坐标

> 状态：已确认并实现。P0、P1 离线通过。P2 真实提问 pending_external。

spec: SPEC-005 的坐标来源。ISSUE-008 的模型一轮只搜一次仍然有效。

## 用户原话（2026-10-22）

只提高详情次数不够。名字没对上的，由页面再按这个名字各搜一次，一条一条查，不交给模型。搜到唯一编号后再查详情。次数提到 12，继续按天轮流。某一天最终仍少于 2 个坐标点，不画线。用户回复「可以」。

## 要改

- 行程里某个地点，在本轮已有搜索结果里对不上唯一一条时，页面用这个地点名再调一次 `maps_text_search`。每个名字最多一次。
- 补搜结果只有唯一一条对得上，才拿它的编号去查 `maps_search_detail`。对上多条，或一条都没有，不查详情，这个地点不上图。
- 页面自己发出的补搜和详情，加在一起最多 12 次。按天轮流用这些次数，不把名额全部给前几天。
- 这些调用一条一条发，不并发。
- 测试写在 `tests/test_itinerary.py`。第 3 天有一个名字不在第一次搜索里：页面会用这个名字再搜一次；结果唯一时，详情被调用，地图上这一天能出现该点。结果有多条时，不调用详情。已有测试里「西湖」对上多条仍不上图，「B1、B2 已够就不再查 B3」仍然成立。

## 不改

- 模型这一轮仍然最多一次 `maps_text_search`、一次 `maps_weather`。补搜不交给模型。
- 某一天有坐标的地点少于 2 个，仍然不画线。点够 2 个才画。
- 聊天框、标点颜色、第几天按钮、行程卡编号。
- 已经生成并存在卡片里的旧行程不回头重查。新的一次提问才用新规则。
