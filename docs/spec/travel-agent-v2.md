# Spec: 旅行对话 Agent（修订：结构化行程）

本版冻结后取代 `SPEC-002`。SPEC-002 的全部内容和 AC-001 至 AC-008 原样继承，下面只写新增和改动。SPEC-002 在本版冻结前保持 Frozen。

## 为什么要修订

地图要画点和单天路线，界面需要知道「第几天、哪个时段、哪个地点、坐标」。SPEC-002 里模型只交一段文字，画不出地图。

## 新增核心功能

- [ ] 每轮回答同时产出一份结构化行程：天、时段、地点名、做什么、怎么去、提醒
- [ ] 坐标由宿主补，不由模型写：用当次 `maps_text_search` 等工具返回里的地点名和坐标匹配
- [ ] 回答类型分两种：行程，或只回答问题（如天气）。后者不改行程、不出地图

## 改动的 Agent 方案

| 项 | 选择 | 没选什么、为什么 |
|---|---|---|
| 谁做决定 | 新增：坐标只能来自本轮高德工具返回，由宿主按地点名匹配后写入；匹配不到的地点只出现在文字里，不上图 | 不让模型写坐标：模型会编出看起来合理的数字 |
| 上下文与记忆 | 新增结构化行程作为会话状态的一部分：本轮查询失败时保留上一份行程；用户改天数时以新天数重排 | 不把整份结构化行程再塞回模型上下文：模型仍只看上一轮原话和最终答案 |
| 用户/调用方路径 | 只问天气这类问题，回答类型为「只回答」，界面不出地图，行程不变 | 不每问一句都重排行程 |

其余各项（控制方式 ReAct、只读工具、不建知识库、注入失败即停）不变。

## 规格未写、合理用户会踩

| 输入或情况 | 合理用户期望 | 落到哪条 AC |
|---|---|---|
| 地点在高德里查不到坐标 | 文字照常出现，地图上没有这个点，不报错 | AC-102 |
| 两个地点同名（如两家同名火锅店） | 只用本轮工具返回、且在本城市的那一个；不确定就不上图 | AC-102 |
| 「改成七天」但这次查询失败 | 保留上一份三天的行程，并说明没查到 | AC-104 |

## 新增验收标准

| ID | 验收项 | 级别 | 证据等级 |
|---|---|---|---|
| AC-101 | 「成都三天」的回答能解析成三天、每天至少一个地点，每个地点有时段和名称 | P0 | E0 单元测试 + E2 真实回答 |
| AC-102 | 坐标全部来自本轮工具返回；匹配不到的地点没有坐标，不上图 | P0 | E0 单元测试 |
| AC-103 | 只问天气时回答类型为「只回答」，不产生新行程，旧行程不变 | P1 | E0 + E2 |
| AC-104 | 本轮查询失败时，结构化行程保持上一份 | P1 | E0 |
| AC-105 | 结构化输出解析失败时，文字回答照常显示，界面不出地图，不崩溃 | P1 | E0 |
