# Spec: 旅游助手

## 一句话描述

给一个人在本地网页里问行程和天气：助手调用高德查实时信息，并记住本会话里还生效的城市、天数和节奏。

## 子 Spec 清单

| spec_id | 能力 | 一句话描述 |
|---|---|---|
| SPEC-002 | 旅行对话 Agent | 多轮追问、调用地图工具、按会话记住行程状态 |
| SPEC-003 | 前端现代化 | 已有界面规格，见 `docs/spec/frontend-modernization.md`。本次不改它的范围 |
| SPEC-004 | 行程加地图界面 | 详细文字行程为主、电子地图为辅，见 `docs/spec/trip-map-ui.md` |
| SPEC-005 | 旅行对话 Agent 修订 | 结构化行程与坐标来源，冻结后取代 SPEC-002 |

## 边界条件（不在范围内）

- 不做登录、多用户账号、服务端长期保存对话。
- 不把架构换成 Deep Agents、手写 LangGraph，也不加向量库。
- 不对只读的地图查询加人确认。
- 不提供给别的系统调用的 HTTP API。
- 不接入阿里云 Token Plan（该密钥不能用于应用后端）。

以上四条里，前三条来自已确认的产品边界（`PLAN.md`「不要做」、`docs/spec/frontend-modernization.md`）。Token Plan 是 2026-10-19 对话里的决定。

## 非功能性需求

| 维度 | 要求 |
|---|---|
| 性能 | 单轮工具预算默认 1 轮（一轮内可以并行多个工具）。这是现有代码，本次沿用，要改须单独确认 |
| 安全 | API 密钥只来自环境变量，不进仓库、不进日志。坐标在界面日志里保留三位小数 |
| 可维护性 | 行程状态由本会话的用户原话每轮重算，不放进程级全局变量 |

## 技术约束

| 项 | 选择 | 理由与代价（没选什么） | 谁定的 |
|---|---|---|---|
| 语言 | Python | 现有项目。不改写成 TypeScript | 沿用现有项目 |
| Agent 框架 | LangChain `create_agent` + 中间件 | 工具不多，中间件能卡住城市和预算。不换 Deep Agents，不手写图 | 用户已确认不换 |
| 模型 | `qwen3.8-flash`，千问兼容接口 | `qwen-turbo` 已下线。不接 Token Plan | 用户已确认 |
| 界面 | Gradio，本地 `python main.py` | 已有界面。SPEC-004 的布局另议，不改这条全局默认 | 沿用 SPEC-003 |
| 地图 | 高德 MCP | 现有只读工具。不自建 POI 库 | 沿用现有项目 |

## 验收标准

项目级只要求：子 Spec 的 P0 不互相打架。SPEC-002 不得要求修改 SPEC-003 已冻结的「后端零改动」——那条只约束前端现代化那一次改动，不约束以后的 Agent 修复。

| ID | 验收项 | 级别 |
|---|---|---|
| AC-001 | SPEC-002 与 SPEC-003 同时成立：界面仍是本地 Gradio；Agent 行为以 SPEC-002 为准 | P0 |
