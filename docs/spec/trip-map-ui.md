# Spec: 行程加地图界面

继承 `SPEC-001` 的全局边界。Agent 行为以 `SPEC-002`（及其修订 `SPEC-005`）为准。本 Spec 不改 `SPEC-003` 的已冻结范围；SPEC-003 写死了「后端零改动、仅 Gradio 外观」，所以界面重做另立本份。

## 一句话描述

用户说出城市和天数后，左边看到详细到时段、交通和提醒的文字行程，右边用电子地图看这一趟的地点和选中那一天的先后顺序。

## 核心功能

- [ ] 文字行程为主：第几天 → 时段 → 地点 → 做什么、怎么去、提醒
- [ ] 电子地图为辅：标出这一趟全部地点；只画当前选中那一天的路线
- [ ] 天数按钮：第 1 天到第 N 天，N 不限，布局不变
- [ ] 点地图上的地点，文字滚到对应那一行并高亮
- [ ] 只问天气这类不涉及行程的问题：不出地图，只给答案，并提示当前行程没变
- [ ] 没查到：保留原来的文字和地图，写明这次没查到、没有新增

## 边界条件（不在范围内）

- 订票、登录、多人协作、拖拽改顺序
- 手绘地图和脚印（v0.7 留到以后）
- 离线地图、导出 PDF 或表格
- 地图上画真实导航路径。线只表示先后顺序，按直线连接；真实路线规划另立需求

## 非功能性需求

| 维度 | 要求 |
|---|---|
| 版式 | 宽屏时文字约 58%、地图约 42%；窄屏文字在上，地图在下且高度不超过约 260px。地图不能压过文字 |
| 安全 | 高德 Web 端 JS 的 key 与 MCP 用的 key 分开，都只来自环境变量；页面不暴露模型密钥。日志里的坐标仍按三位小数脱敏，地图本身用完整坐标 |
| 失败 | 地图加载失败时，文字行程照常可读，地图区写明地图暂不可用 |

## 用户使用路径与信息架构

- 核心任务主线：说出城市和天数，读清每天怎么安排，并在地图上确认地点在哪、一天顺不顺。
- 关键路径步骤：打开页面 → 输入「成都三天」→ 看到第 1 天的详细文字和地图上第 1 天的路线 → 点第 2 天 → 输入「改成七天」→ 同一页出现七个天数按钮。
- 主内容：左侧文字行程。
- 次要内容：右侧地图；「开发者」抽屉里的过程日志，默认收起。
- 端到端可验收场景：见 AC-001 至 AC-005。
- 评审入口与版本：`prototypes/travel-ui-v0.11.html`（v0.11）。外观以后按 Google Stitch 视觉稿替换，结构不变。
- 确认范围：2026-10-20 用户原话「电子地图为主，但是电子地图也别弄得太大，文字详细的文字版清晰展示给用户也同样重要」；选定 v0.8 结构、问天气不出地图。同日用户回复「确认」，确认 v0.11 的结构与六种状态（空、没说天数、三天、七天、没查到、只问天气）、本 Spec、SPEC-005、方案 A 和 M2 拆分。外观仍按 Stitch 稿替换。
- 未展示页面如何继承：没有登录、设置页。「开发者」抽屉沿用同一套颜色与字号。

## 验收标准

| ID | 验收项 | 级别 |
|---|---|---|
| AC-001 | 真实输入「成都三天」：文字列出三天，每个地点含时段、做什么、怎么去；地图标出全部有坐标的地点，只画第 1 天路线 | P0 |
| AC-002 | 点「第 2 天」：地图只画第 2 天路线，其他天的点变淡；点地图上的地点，文字对应行高亮 | P0 |
